# แผน TDD สำหรับเว็บห้องเสมือน

สถานะร่างเพื่อรีวิว · ผู้ใช้ล็อกอินแล้วเข้าพื้นที่สาธารณะเดียวกันทันที เห็นผู้เล่นออนไลน์คนอื่นและการเคลื่อนไหวแบบเรียลไทม์ ควบคุมตัวละครในแมพ 2D มุมมองจากด้านบนด้วย WASD หรือปุ่มลูกศร บัญชีแอดมินใช้โหมดแก้ผังบนหน้าเว็บเดียวกันเพื่อวาง ย้าย และลบเฟอร์นิเจอร์ เมื่อบันทึกแล้วทุกคนเห็นผังใหม่โดยอัตโนมัติ

## สัญญาที่ใช้

| การ์ดเว็บ | ผู้ผลิต | การเชื่อมต่อและ fixture |
|---|---|---|
| AUTH-020 | CONTRACT-010, AUTH-010 | ใช้ `POST /auth/login`, `GET /auth/me` และ `POST /auth/logout` ทดสอบกับบัญชีใช้งานได้ ข้อมูลล็อกอินผิด และเซสชันหมดอายุ |
| MAP-010 | CONTRACT-010 | ใช้ `room-definition.v1.json` และ fixture ตำแหน่งจาก server เพื่อวาดแมพกับตัวละคร และแปลงปุ่มเป็นทิศทาง |
| LIVE-020 | CONTRACT-010, LIVE-010, MAP-010 | เชื่อม `/rooms/public/live` หลังยืนยันเซสชัน ส่ง `input` และใช้ `welcome`, `players`, `layout.updated` ทดสอบผู้เล่นเข้า/ออก การเชื่อมต่อใหม่ และผังต่าง revision |
| ROOM-020 | CONTRACT-010, ROOM-010, LIVE-020 | อ่านและบันทึกผ่าน `GET/PUT /rooms/public/layout` โดยใช้ role จาก `/auth/me` ทดสอบผังว่าง ตำแหน่งผิดกติกา สิทธิ์แอดมิน และ revision ชนกัน |

เว็บส่งทิศทางให้ API คำนวณตำแหน่ง แล้ววาดผู้เล่นตามสถานะที่ได้รับจากเซิร์ฟเวอร์ ส่งทิศทางศูนย์เมื่อปล่อยปุ่ม เสียโฟกัส หรือเปิดโหมดแก้ผัง เมื่อการเชื่อมต่อขาด ให้แสดงสถานะและลองเชื่อมใหม่อัตโนมัติ เมื่อได้รับ `welcome` ใหม่ให้แทนสถานะผู้เล่นและผังทั้งชุด ถ้าเซสชันหมดอายุให้กลับหน้าล็อกอิน

ร่างผังของแอดมินแสดงเฉพาะตอนแก้ไข เมื่อบันทึกสำเร็จผู้เล่นทุกคนเห็นผังที่ API ยืนยันผ่าน revision ล่าสุด ถ้าแอดมินสองคนแก้พร้อมกันและได้รับ `409 ROOM_REVISION_CONFLICT` ให้เก็บร่างไว้ แสดงข้อขัดแย้ง และให้แอดมินเลือกโหลดผังล่าสุดก่อนเริ่มแก้ใหม่

### RED ที่ต้องเห็นก่อนเขียนโค้ด

| การ์ด | RED scenarios |
|---|---|
| AUTH-020 | **RED-1** ล็อกอินสำเร็จแล้วเข้าแมพสาธารณะทันที และ refresh แล้วใช้เซสชันเดิม **RED-2** ข้อมูลผิดแสดงข้อความที่ฟอร์ม และเมื่อ `/auth/me` คืน `401` หน้าเปิดที่ฟอร์มล็อกอิน **RED-3** หลัง logout เปิด URL แมพโดยตรงแล้วถูกพากลับล็อกอิน |
| MAP-010 | **RED-1** วาดผู้เล่นสองคนตามพิกัดจาก fixture และอัปเดตตำแหน่งเมื่อ snapshot เปลี่ยน **RED-2** WASD และปุ่มลูกศรส่งทิศทางตรงและแนวทแยงตาม schema **RED-3** ปล่อยปุ่ม เสียโฟกัส หรือเปิดโหมดแก้ผังแล้วส่งทิศทางศูนย์ |
| LIVE-020 | **RED-1** หลังยืนยันเซสชันเชื่อมเข้าแมพทันทีและแสดงผู้เล่นตาม `welcome` และ `players` **RED-2** ผัง revision ใหม่อัปเดตทันที และข้อความ revision เก่าไม่ย้อนผัง **RED-3** reconnect แทนสถานะเก่าด้วย `welcome` ใหม่ ส่วนเซสชันหมดอายุพากลับล็อกอิน |
| ROOM-020 | **RED-1** แอดมินวาง ย้าย ลบ และบันทึกด้วย revision ล่าสุด ส่วนผู้ใช้ทั่วไปเห็นผังโดยไม่มีปุ่มแก้ไข **RED-2** ตำแหน่งเกินขอบ ทับจุดเกิด หรือทับของชิ้นอื่นถูกปฏิเสธที่ UI **RED-3** ถ้า API ตอบ `409` ให้เก็บร่างไว้ แสดงข้อขัดแย้ง และใช้ revision ใหม่หลังเลือกโหลดผังล่าสุด |

## เกณฑ์ตรวจรับร่วม

Browser E2E เปิดสาม browser contexts ด้วย API จริง ใช้ผู้เล่นสองบัญชีกับแอดมินหนึ่งบัญชี ผู้เล่นสองคนล็อกอินแล้วเห็นกันในแมพทันที เมื่อคนหนึ่งเดินหรือออกจากระบบ อีกคนเห็นผล แอดมินย้ายเฟอร์นิเจอร์แล้วผู้เล่นทั้งสองเห็นตำแหน่งใหม่โดยไม่ต้องรีเฟรช หลังรีเฟรชยังเห็นผังล่าสุด และ PUT จากบัญชีผู้เล่นได้ `403` งานส่วนนี้ปิด integration gate เมื่อ AUTH-010, ROOM-010 และ LIVE-010 ผ่านเทสต์ฝั่ง API และ browser flow นี้ผ่าน

ทำทีละการ์ดตาม workflow ของ repo เริ่ม Phase RED หลังการ์ดเป็น `ready` เขียนเฉพาะเทสต์และตรวจว่า assertion ล้มเพราะพฤติกรรมที่ยังขาด เปิด Draft PR เข้า `develop` แล้วรอ Dev ยืนยัน RED ก่อนทำ GREEN และ REFACTOR รัน lint, typecheck และ test ก่อนส่งรีวิว
